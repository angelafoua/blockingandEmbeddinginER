================================================================================
                    RECURSIVE LSH IMPLEMENTATION PLAN
                         SUMMARY & QUICK REFERENCE
================================================================================

PROJECT: Recursive LSH for Entity Resolution with Data Quality Variations

PROBLEM:
  Records have data quality variations (john/jon, smith/smyth, ny/new york)
  Current token-based blocking treats these as different tokens
  Result: True duplicates are not matched

SOLUTION:
  1. Create word signatures that group variations
  2. Use Recursive LSH to efficiently bucket similar records
  3. Match and merge duplicates

================================================================================
                              YOUR APPROACH
================================================================================

                      WORD SIGNATURES
                            ↓
     john, jon, jhon → SIG_JOHN
     smith, smyth → SIG_SMITH
     new york, ny → SIG_NEWYORK
                            ↓
                   RECURSIVE LSH
                            ↓
     Level 1: Group by all shared signatures
     Level 2: Refine by subsets of signatures
     Level 3: Further refinement (stop at max_depth)
                            ↓
                      MATCHING
                            ↓
     Within each bucket: Compare, apply rules, compute similarity
                            ↓
                    TRANSITIVE CLOSURE
                            ↓
     If A=B and B=C then A=B=C
                            ↓
                       MERGING
                            ↓
     Final deduplicated dataset

================================================================================
                       CONFIGURATION PARAMETERS
================================================================================

Signature Generation:
  method: 'fuzzy'                    ← How to group word variations
  similarity_threshold: 85           ← 0-100, higher = stricter

LSH Bucketing:
  num_perm: 128                      ← MinHash signature size
  threshold: 0.5                     ← Jaccard similarity (0-1)
  max_depth: 3                       ← Max recursion depth
  min_bucket_size: 2                 ← Stop refining when < this

Record Matching:
  threshold: 0.8                     ← Similarity threshold (0-1)
  method: 'jaccard'                  ← Token overlap

Merging:
  strategy: 'union'                  ← How to merge records

See config/default_config.yaml for full documentation
